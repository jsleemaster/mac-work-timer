# 주간 근무시간 잔액 기능 설계

## 목표

Mac Work Timer가 월요일부터 금요일까지의 순 근무시간을 합산해 주 40시간 충족 여부를 보여준다. 점심시간은 근무시간에서 제외하고, 초과 근무분은 특정 날짜에 자동 배분하지 않는다. 사용자는 남은 주중 어느 날이든 그 시간을 자유롭게 사용할 수 있다.

화면 문구는 통제하거나 지시하는 느낌보다 짧고 편안한 표현을 사용한다.

```text
오늘 퇴근       18:35
이번 주 여유    +23분
오늘 다 쓰면    18:12
```

## 확정된 동작

- 한 주는 한국 시간 기준 월요일 00:00부터 다음 월요일 00:00 전까지다.
- 정상 근무일 목표는 순 근무 8시간이고, 주간 목표는 40시간이다.
- 완료된 근무일의 순 근무시간은 `퇴근 - 출근 - 점심 겹침 시간`으로 계산한다.
- 점심시간은 12:00~13:00으로 두고, 출퇴근 구간과 실제로 겹친 시간만 뺀다.
- 연차처럼 하루 전체가 인정되는 기록은 8시간, 오전·오후 반차는 4시간을 근무 인정시간으로 더한다.
- 공휴일이나 회사 휴무처럼 GW에 인정 기록이 있는 경우 그 기록의 인정시간을 사용한다. 기록이 없다면 앱이 임의로 시간을 만들지 않는다.
- 퇴근 기록이 없는 과거 날짜는 완료 시간에 포함하지 않고 데이터 미완성 상태로 표시한다.
- 오늘 진행 중인 시간은 기존 출근 타이머가 담당한다. 주간 여유 계산은 완료된 이전 근무일 기록을 기준으로 오늘 시작 시점의 사용 가능 시간을 만든다.
- 양수인 주간 여유는 특정 날짜에 예약하거나 소진 처리하지 않는다. 다음 GW 조회에서 실제 퇴근 기록이 반영되면 잔액이 다시 계산된다.
- `오늘 다 쓰면`은 `오늘 퇴근 - 사용 가능한 주간 여유`다. 사용 가능한 여유가 없으면 오늘 퇴근 시각과 같게 표시한다.
- 주간 부족 시간이 있을 때는 `이번 주 부족 14분`처럼 부호 대신 자연어로 표시한다. 이 부족분을 오늘 모두 채운 시각은 별도 보조 문구로 나타낼 수 있지만, 자동으로 오늘의 의무 목표로 확정하지 않는다.

## 접근 방식 비교

### 1. GW 주간 표 자동 조회 + 마지막 정상 결과 캐시 — 채택

GW의 개인근태현황 표에서 이번 주 출근, 퇴근, 휴가·반차 기록을 읽는다. 성공한 결과는 로컬 상태에 저장해 일시적인 로그인 만료나 네트워크 오류 때도 마지막 계산값을 유지한다.

- 장점: 앱을 주중에 처음 실행해도 월요일부터의 기록을 복원할 수 있다.
- 장점: 실제 GW 기록과 같은 근거를 사용하며 수동 입력이 필요 없다.
- 단점: GW 화면 구조가 바뀌면 파서를 함께 수정해야 한다.

### 2. 앱이 매일 로컬에서만 출퇴근 시간을 누적

앱이 실행된 동안의 출근과 퇴근만 저장한다.

- 장점: GW 주간 화면 구조에 덜 의존한다.
- 단점: 앱이 꺼져 있거나 주중에 처음 설치되면 기록이 빠진다.
- 단점: GW에서 정정된 근태와 휴가 기록을 반영하기 어렵다.

### 3. 사용자가 주간 시간을 직접 입력

주간 누적시간과 휴가시간을 사용자가 수정한다.

- 장점: 모든 예외를 사람이 바로 보정할 수 있다.
- 단점: 매일 관리해야 하므로 이 앱의 자동 타이머 목적과 맞지 않는다.

자동 조회를 기본으로 하고 마지막 성공 결과 캐시를 보조로 쓰는 1번을 채택한다. 수동 수정 UI는 이번 범위에 넣지 않는다.

## 구성요소

### `WeeklyAttendanceRecord`

GW 표의 하루 또는 인정시간 행을 표현한다.

- 날짜
- 출근 시각
- 퇴근 시각
- 근태 항목과 구분
- 인정시간
- 원본 행 요약

출퇴근 행과 휴가 행이 같은 날짜에 둘 이상 있을 수 있으므로 날짜를 고유 키로 가정하지 않는다.

### `WeeklyAttendanceParser`

GW 개인근태현황의 HTML 또는 화면 텍스트를 행 단위 기록으로 변환한다. 현재의 오늘 출근 파서와 분리해, 기존 로그인·타이머 동작을 깨뜨리지 않는다.

### `WeeklyWorkBalanceCalculator`

파싱이나 UI를 모르는 순수 계산기다.

- 출퇴근 구간과 점심시간의 겹침 계산
- 실제 근무시간과 휴가 인정시간 합산
- 이전 완료일 기준 주간 여유·부족 계산
- 오늘의 정상 퇴근 시각 계산
- 오늘 여유를 전부 사용할 때의 시각 계산

### `WeeklyWorkSummary`

UI가 바로 사용할 수 있는 계산 결과다.

- 이번 주 완료 근무시간
- 주간 목표시간
- 여유 또는 부족 시간
- 오늘 퇴근 시각
- 오늘 다 쓸 때의 시각
- 마지막 정상 조회 시각
- 미완성 기록 유무

### GW 조회와 캐시

현재 로그인 세션을 재사용해 개인근태현황을 읽기 전용으로 조회한다. 출퇴근 등록·수정 요청은 보내지 않는다. 조회 성공 시 이번 주 기록과 조회 시각을 상태 저장소에 넣는다. 실패 시 오늘 출근 타이머는 계속 동작하고, 주간 정보에는 마지막 업데이트 시각을 함께 표시한다.

## 데이터 흐름

1. 앱이 기존 방식으로 오늘 출근 기록을 불러온다.
2. 같은 읽기 전용 로그인 세션으로 이번 주 개인근태현황을 조회한다.
3. `WeeklyAttendanceParser`가 여러 행을 구조화한다.
4. `WeeklyWorkBalanceCalculator`가 완료된 이전 날짜와 인정시간을 합산한다.
5. 오늘 출근 시각을 기준으로 `오늘 퇴근`과 `오늘 다 쓰면`을 계산한다.
6. AppModel이 요약을 노출하고 펫 패널과 메뉴바가 같은 값을 사용한다.
7. 실제 퇴근 기록이 GW에 반영된 다음 조회에서 주간 여유가 자동으로 갱신된다.

## UI

펫 패널의 기존 퇴근 시각 주변에 주간 정보를 세 줄 이내로 배치한다.

```text
오늘 퇴근       18:35
이번 주 여유    +23분
오늘 다 쓰면    18:12
```

- `이번 주 여유`가 0이면 `이번 주 딱 맞아요`로 표시한다.
- 음수이면 `이번 주 부족 14분`으로 표시한다.
- 주간 데이터를 아직 읽지 못했으면 기존 `오늘 퇴근`만 보여주고 잘못된 0분을 표시하지 않는다.
- 캐시를 사용 중이면 상세 메뉴에서 `마지막 확인 10:24`를 보여준다. 작은 펫 패널에는 오류 문장을 계속 노출하지 않는다.
- 메뉴바 카운트다운과 퇴근 알림은 `오늘 다 쓰면`을 기준으로 한다. 메뉴 상세에는 `오늘 퇴근`도 남겨 사용자가 시간을 아껴둘 수 있게 한다.
- 주간 3줄 묶음은 가로 10pt, 세로 6pt의 안쪽 여백을 두어 배경 가장자리에 붙지 않게 한다.

### 주간 데이터가 없을 때의 로그인 경로

- 로컬 출근 타이머가 이미 시작됐더라도 완성된 주간 요약이 없으면 `주간 기록 연결하기`를 표시하고, 펫 클릭 또는 메뉴의 `GW 로그인 열기`로 인증 화면을 연다.
- 이 로그인 창은 오늘 출근 기록을 다시 만들기 위한 전용 화면이 아니라, 현재 WKWebView 세션을 인증해 이번 주 개인근태현황을 읽기 위한 복구 경로로도 사용한다.
- 인증이 끝나 주간 기록을 정상적으로 읽으면 기존처럼 로그인 창을 닫고 펫 화면에 주간 3줄 정보를 표시한다.

## 오류 처리

- 로그인 만료: 기존 오늘 타이머를 유지하고 마지막 정상 주간 요약을 사용한다.
- 네트워크 오류: 캐시가 있으면 캐시와 마지막 확인 시각을 표시한다. 없으면 주간 문구만 숨긴다.
- 표 구조 변경 또는 파싱 실패: 일부 행만 조용히 추정하지 않고 해당 조회 전체를 실패로 처리한다.
- 퇴근 누락: 누락 행을 합산하지 않고 상세 메뉴에 확인이 필요한 날짜를 표시한다.
- 미래 시각, 퇴근이 출근보다 빠른 행, 같은 원본 행 중복은 검증 단계에서 제외하고 진단 정보로 남긴다.

## 호환성과 저장

기존 상태 파일을 계속 읽을 수 있도록 새 주간 캐시 필드는 선택값으로 디코딩한다. 앱 업데이트 직후 주간 캐시가 없어도 기존 오늘 타이머, 반차 선택, 펫 상태는 그대로 유지한다.

## 테스트와 검증

### 단위 테스트

- `09:21~18:44`에서 점심 1시간을 제외해 8시간 23분이 되는지 검증한다.
- 월요일 `+23분`, 화요일 `-14분`이면 수요일 시작 잔액이 `+9분`인지 검증한다.
- 수요일 09:35 출근 시 `오늘 퇴근 18:35`, `오늘 다 쓰면 18:26`인지 검증한다.
- 점심시간 일부만 겹치는 근무와 전혀 겹치지 않는 근무를 검증한다.
- 하루 출퇴근 행과 오후 반차 4시간 행이 함께 있을 때 중복 없이 합산하는지 검증한다.
- 퇴근 누락, 중복 행, 주 경계, 시간대, 기존 상태 파일 디코딩을 검증한다.

### 통합·UI 검증

- GW 응답 fixture에서 여러 주간 행을 파싱한다.
- 조회 실패 후 마지막 캐시가 유지되는지 검증한다.
- 펫 패널과 메뉴 상세가 같은 세 시각·잔액을 표시하는지 확인한다.
- `swift test`와 앱 번들 빌드를 실행한다.
- 앱을 실제로 띄워 양수·0·음수·데이터 없음 상태를 확인한다.
- 브라우저 기반 GW 화면 점검이 필요하면 저장소 지침에 따라 Playwright CLI만 사용한다.

## 제외 범위

- GW 출퇴근 등록 또는 수정
- 주간 여유를 날짜별로 예약·차감하는 기능
- 사용자가 직접 근무시간을 편집하는 기능
- 월간 정산과 급여 계산
- 회사별로 다른 점심시간을 설정하는 UI
